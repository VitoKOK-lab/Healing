# LINE OA 喵喵占卜 v3 — 設計規格書

> 2026-08-13 與店主逐題確認定案。取代先前的 v2 規格書與 Kimi 增補篇。
> 本文件是「做什麼、為什麼」;實作步驟由後續的 implementation plan 拆解。

---

## 0. 定位與護城河(所有取捨對著這三條檢查)

1. **實體店 × 線上導流**:占卜是導流,變現在寶石飾品與到店體驗。線上功能永遠要留一條回到實體的路。
2. **貓 IP(本喵)**:客人記得的是那隻貓。人設資產持續累積,不做會稀釋人設的功能。
3. **敢說真話的機制**:牌面指向不利就誠實說,不中性化、不加免責降溫。這是客人覺得「這是真的占卜」而願意付費的核心。

不是護城河、只是及格線:價格階梯、LLM 技術、牌義資料庫。

## 1. 產品階梯

| 層 | 價格 | 內容 | 目的 |
|---|---|---|---|
| 免費日抽 | $0,每日 1 次 | 單張牌 + 本喵型短評(2–3 句) | 每天把人拉回來的鉤子 |
| 加深解讀 | **NT$20** | 把「日抽同一張牌」展開成四段式完整解讀 | 完成第一次付款,嘗到付費甜頭 |
| 深度占卜 | **NT$149**(預設;上線前可調至 199,程式以設定值處理) | 自選主題 → 完整牌陣 → 四段式長文 | 正價商品 |

- NT$20 的付款動機:客人已被日抽那張牌勾住,不必重抽、不必再選題。
- 牌陣沿用現有六種:核心指引 / 時間之流 / 二擇一 / 關係十字 / 賽爾特十字 / 生命之樹。
- 不適合占卜的題目(輕生、醫療、明牌、生死、天下事、他人隱私、問確切時間、問太遠)沿用現有攔截詞庫,在**扣款之前**擋下;危機類固定接 1925 安心專線,不賣任何東西。

## 2. 核心運算(全部在伺服器)

前端只送**切牌手勢**(切點 0–1 與滑動軌跡雜湊成種子);抽牌、正逆位、tier 全部後端算,回傳結果。前端不再持有任何可竄改的運算。

### 2.1 T1–T5 定調機制(從牌面算)

- 每張牌 × 正逆位給吉凶分(-2 ~ +2,牌庫逐張標定);大阿爾克那 ×1.5 加權;牌陣位置有權重(例:「最後落點」「未來」權重高於「過去」)。
- 加權總分正規化後落入五級:T1 大吉 / T2 順 / T3 中性有變數 / T4 阻力 / T5 不利。
- 方向對映:T1 +1、T2 +1、T3 0、T4 −1、T5 −1。
- 牌庫分數設計目標:自然分布下 T4+T5 ≈ 34%(以 10 萬次蒙地卡羅模擬驗證,調分不調機率)。
- **同一副牌永遠同一個 tier**:tier 是牌面的函數,不摻任何隨機。經得起懂牌客人的檢驗。

### 2.2 生成前鎖定方向

tier 先算好才呼叫模型,prompt 明示:「本次占卜方向已由系統計算鎖定,你只負責表達,不得中性化、不得加免責。」

## 3. 輸出結構

### 3.1 人設分層

- **免費日抽 = 本喵型**:現行網頁版聲線(「本喵幫你看過了喵」),可愛、好分享。
- **付費解讀 = 收斂專業型**:無語尾助詞、無表情符號;萌感只准出現在動作描寫(「牌翻開時,貓尾巴掃過桌面」),每段最多一處。付費前後的質感落差本身就是價值感來源。

### 3.2 付費四段式(NT$20 與正價共用)

> **2026-08-16 依店主決定放寬**:段數不再硬性要求剛好四段、心理視角段不再強制問句收束、務實段不再強制時間尺度。三條都是「像不像人在講話」的形式偏好,不是誠信底線;寫死反而綁住表達,也讓模型為了湊格式而失焦(P9 驗收實測:複雜牌陣常因湊不齊格式而整篇退回)。下表現在描述的是**內容要涵蓋的四件事**,不是格式檢查表——分段由模型依牌面自己拿捏。
> **方向誠實(T4/T5 不得中性化)不在放寬之列**,那是承諾不是形式,仍由 §4.1 第 8 條的二次分類把關。

| 要涵蓋 | 規則 |
|---|---|
| 定調 | 第一句就給出方向,不繞彎、不寒暄 |
| 心理視角 | 阿德勒取向的內在梳理,**不得出現「阿德勒」「心理學」字樣**;問句收束通常最有力但不強制 |
| 務實 | 納瓦爾式的具體槓桿,不得出現「納瓦爾」;有具體時間尺度(這週、三個月內)更好落地,牌面沒指向特定時機時不必硬加 |
| 收尾 | 五種收法輪替(約定/反問/畫面/斷言/觀察),從牌面長出來;約定式才給行動,時間點依牌面選,禁「明天起床」型罐頭開場(2026-08-14 依店主回饋從「一件事」改制) |

- 徵兆必附出處:指出徵兆的同一句話要有〔牌名正/逆位〕與明確方向,全篇至少三處。
- 標記規則:〔〕框牌名與正逆位;【】框 3–5 個有內容的判斷(4–10 字),不框牌名、不框空詞。
- 引號一律「」『』;繁體中文台灣用語;禁 Markdown 符號、禁條列。

## 4. 生成模型與品管管線

| 用途 | 模型 |
|---|---|
| 免費日抽短評 | 依 `MODEL_PROVIDER` 切換 |
| 付費解讀 | 依 `MODEL_PROVIDER` 切換(現行:Kimi K2.6) |
| T4/T5 方向二次分類 | Claude Haiku(有金鑰時優先,不讓生成模型替自己的降溫護短) |

**2026-08-17 現行決定:兩層都用 Kimi K2.6(`MODEL_PROVIDER=kimi`)。**

一度把付費層寫死 Claude,理由是「Kimi 格式遵守率不到五成」——**那個判斷是錯的**。真因是 guards 把「后」列進簡體字黑名單,而牌庫有皇后與四張王后,一抽到就整篇退回(賽爾特十字約半數中招)。修掉誤判後同牌陣公平比較:

| | Kimi K2.6 | Claude Sonnet 5 |
|---|---|---|
| 單次通過率 | 5/6 | 5/6 |
| 秒數 | 14~22s | 15~20s |

兩者同級,Kimi 便宜,故付費層一併回到 Kimi。教訓記在這裡:**看到品質數字變差,先查是不是自己的審核規則誤殺,再懷疑模型能力**。

Claude 仍保留兩個位置:`MODEL_PROVIDER=claude` 可整組切回;T4/T5 方向二次分類優先用 Haiku(不讓生成模型替自己的降溫護短)。若日後改回 Claude,其原有優勢仍成立:台灣用語原生正確、不會自我否定占卜、資料不落地中國。

**兩家共通的坑(已在 code 處理)**:兩個模型的「思考模式」都會吃掉 `max_tokens` 並讓單次超過 60 秒撞上 Vercel `maxDuration`。Kimi 需明確 `thinking:{type:"disabled"}` 且該模式只吃 `temperature: 0.6`;Claude Sonnet 5 起省略 `thinking` 等於預設開啟,同樣要明確關閉。

### 4.1 產出審核(code 層,不靠 prompt 自律)

每次生成後檢查,不合格自動重生成一次(換切入角度),仍不合格取較佳者:

1. 定調段第一句就有方向
2. 收尾段只有一個動作(段數與順序自 2026-08-16 起不檢查,見 §3.2)
3. 無「阿德勒」「納瓦爾」「心理學」字樣
4. 無罐頭句 / 降溫套話(僅供參考、僅供娛樂、雙方共同努力、緣分自有安排、順其自然、相信自己、放下執念、時間會給你答案、科學角度、不要迷信……全清單進 code)
5. 付費層無語尾助詞、無 emoji;萌感每段 ≤1 處且僅限動作描寫
6. 標點為「」非 “ ”;〔〕【】用法正確
7. 逐張報牌句型(「第一張牌…」)不得出現
8. **T4/T5 必跑方向二次檢查(100%,不抽驗)**:Haiku 分類產出方向,與 tier 不符=被中性化,重生成;連續 3 次仍中性化 → 記警報並以本地牌義降級方案出貨,不得出中性化文案

### 4.2 降級方案

模型不可用或審核連續失敗:以牌庫本地牌義組簡版解讀,明示「本喵靈感有點淡」;付費單自動延長效期或退款,不出爛文案收錢。

## 5. 身分、額度、金流

- **載體**:LIFF 網頁(沿用現有洗牌/切牌/貓咪對話資產),進入即取得 LINE userId。
- **額度**:全部記資料庫、綁 LINE userId;localStorage 計次退場。
- **金流**:LINE Pay(店主需申請商家帳號——上線前置作業)。NT$20 小額零摩擦是此選擇的核心理由。
- **去識別化**:呼叫 Claude API 只送問題文字、牌面、tier 與匿名歷史摘要;不送 userId、暱稱、頭像。
- 隱私政策揭露:AI 服務供應商為境外(Anthropic,美國)。

## 6. 黏著度系統

儀式感抓第一次,記憶+日常習慣留下來。

### v1(與主功能同期上線)
1. **本喵記得你**:解讀紀錄入庫;下次占卜 prompt 帶上次問題與牌的摘要,產出有連續性(「上週你問的那件事…」)。有記憶的占卜是罐頭 AI 做不到的差異。
2. **連抽 streak**:連抽 7 天送一次免費加深解讀;LIFF 顯示連續天數,斷簽可惜感。
3. **今日牌分享卡**:直式牌面+一句話結果圖,一鍵分享;落地頁=加 LINE OA 好友。
4. **78 張牌收集圖鑑**:「我的牌歷」頁,抽過點亮,新牌跳「初次相遇」。
5. **關鍵牌特效**(見 §6.2):抽到大牌/關鍵好牌有分級慶祝動畫——爽感即分享動機。

### v1.5(上線後第一波迭代)
5. **應驗回訪**:深度占卜後 3–7 天推播「上次那件事,後來怎麼樣了?」;回覆即應驗見證。
6. **「一件事」隔日回訪**:做了→帶出下一步占卜;沒做→溫柔推一把。解讀變成被盯著的承諾。
7. **生日牌**:生日當天送免費深度占卜+專屬牌面。
8. **到店連動券**:深度占卜結果附到店折扣;店內消費送線上深度占卜(護城河第 1 條的執行)。

### v2
9. **時效事件**:滿月、水逆、節氣、年運限定牌陣與推播。
10. **雙人合抽**:關係占卜邀請對方參與,各切一次牌合成一份解讀。詳細流程與風險對策見 §6.1。
11. **月報**:月底整理「你這個月的牌路」(熟客福利或付費)。

推播紀律:只推「有理由的訊息」(回訪、streak 提醒、生日、時效事件),不推廣告轟炸。

### 6.1 雙人合抽詳細設計(v2,2026-08-13 與店主定案)

定位:把「伴侶同座占卜」(現代實體占卜的既有做法)搬到線上的改編;
關係十字是正典牌陣,雙人各自切牌比單人版更符合「牌反映碰牌的人」的邏輯。
行銷話術照實講:「傳統上要兩個人一起到占卜師面前才做得到」。

**流程**

1. 發起:A 選「雙人關係占卜」→ 選關係類型(伴侶/曖昧/家人/朋友/同事)→ 輸入問題 → **A 付全額**(受邀的 B 永遠免費)
2. A 先切牌:伺服器抽出 A 側的牌,**先不揭曉**(防 A 看到牌不好就不邀了)
3. 邀請:LINE 分享卡「A 邀你一起抽牌,看看你們之間」→ A 傳給 B
4. B 進入:**看不到 A 的原始問題**,邀請頁明示「結果將由 A 決定何時與你分享」→ B 同意 → 切牌
5. 合成:兩側到齊 → 算 tier → 生成解讀 → **只通知 A**
6. **A 發送權(核心規則)**:A 先看完整解讀,按「分享給對方」B 才看得到;不按,B 永遠看不到。發送介面不施壓、不倒數——控制權是付費價值的一部分
7. B 切完牌的等待畫面:「牌已經合起來了,本喵正在看。」+ 轉化鉤「等不及的話,要不要自己抽一張今天的牌?」(B 的懸念導入免費日抽)
8. 解讀構成:共享主解讀 + 各自「只給你的話」私人段(B 的私人段隨 A 發送一併解鎖);A 的原始問題永遠只有 A 看得到

**風險與對策**

| 風險 | 對策 |
|---|---|
| B 不來(最大)| 邀請 48h 有效;24h 未回應提醒 A 一次(可催可換人);逾時**自動轉單人版關係十字**(A 的切牌沿用、系統補 B 側),付款當下講明此規則 |
| 壞消息衝擊 | A 發送權已把「公開處刑」變成 A 的自主決定;另雙人版 T4/T5 落點強制放在「橫在中間的障礙與處理方式」,終局判決只留給單人版 |
| B 的隱私與知情 | B 必須親自同意並切牌(比單人版問他人心思更合倫理);B 看不到 A 的問題;B 的 LINE 身分入庫納入隱私政策 |
| 加好友門檻勸退 B | B 不加好友也能切牌、看共享解讀(保住 A 的體驗);「只給你的話」私人段與日抽權益要加好友才解鎖——加好友從門票變獎勵 |
| 多人非同步狀態機 | 狀態:等待中/已完成/逾時轉單人/A 未發送/已發送;提醒排程一併設計;此複雜度即排 v2 的原因 |
| A 自導自演(兩支手機)| 不防——騙的是自己,費用照付 |

### 6.2 關鍵牌特效分級(v1)

素材沿用、邏輯重寫的原則下,特效全用 CSS + SVG 動畫實作(與手繪貓同一套技術),
不引入外部動畫庫、不依賴額外圖片。稀有度用塔羅天然的結構,不硬造:

| 級 | 觸發 | 表現 |
|---|---|---|
| L0 | 一般小牌 | 現有翻牌動畫 |
| L1 | 大阿爾克那(22 張,天然稀有卡) | 翻牌金邊光暈+星塵粒子,貓耳豎起 |
| L2 | 關鍵好牌:太陽/世界/星星/命運之輪/戀人 | 全螢幕光爆、貓咪撲上來、手機震動(Android `navigator.vibrate`,iOS 無則略過)——目標是讓人想截圖 |
| 初遇 | 圖鑑新牌 | 翻牌後「新收藏!」揭幕層 |
| T1 | 結果頁大吉 | 輕撒花 |

原則:特效只用來慶祝。逆位與沉重牌不做嚇人特效(最多色調沉一點),壞消息由文字溫柔地說。

## 7. 架構與資料模型

同一個 Healing repo、同一個 Vercel 專案(healingasmr)。

```
app/liff/            LIFF 前端(沿用 site-static/tarot/assets 的牌面、影片、貓、音效)
app/api/v2/
  draw/              POST 切牌手勢 → 伺服器抽牌+tier → 回牌面(不回解讀)
  reading/           POST 產生解讀(依層級走 Haiku/Sonnet + 審核管線)
  credits/           GET 額度與 streak 狀態
  payments/linepay/  request / confirm / webhook
  collection/        GET 牌歷圖鑑
lib/tarot/
  deck.ts            牌庫+吉凶分表
  tier.ts            tier 計算(純函數,可蒙地卡羅測試)
  guards.ts          審核表(罐頭句、結構、標點、萌感)
  direction.ts       T4/T5 二次分類
prisma:新增 User(lineUserId)、Reading(牌面/tier/文本/層級)、Purchase(LINE Pay 單)、
       DailyDraw(日抽+streak)、CardSeen(圖鑑)
```

現況不動的部分:`site-static/tarot/`(index/desk)照常營業;desk.html 是否接 v2 引擎,LIFF 版穩定後另案。既有 `/api/tarot/*` 與 `TarotShare` 保留給現場 QR 流程。

## 8. 測試與驗收

- `tier.ts` 純函數:單元測試 + 10 萬次蒙地卡羅驗證 T1–T5 分布(T4+T5 ≈ 34%,誤差 ±3%)。
- `guards.ts`:每條審核規則有正反例測試。
- 生成品質:20 組牌面(五級各 4 組,T3/T5 為重點)人工審核,通過率 ≥85% 才上線付費層;T4/T5 中性化率 >20% 視為未通過。
- 金流:LINE Pay sandbox 全流程(request→confirm→webhook→額度入帳→退款)。
- 去識別化:單測驗證 API 請求體不含 userId/暱稱。

## 9. 非目標(明確不做)
